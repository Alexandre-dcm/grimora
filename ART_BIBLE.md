# ABYSSBOUND — ART BIBLE

Source of truth for every pixel in the game. Read this before authoring a single new asset.

---

## 1. Visual philosophy

Abyssbound is a **dark fantasy pixel-art roguelite**. The dungeon is old, wet, forgotten and
hostile. Light is rare and precious. Stone remembers. Something down there is still awake.

Five words that must always be true of a new asset:

1. **Handcrafted** — deliberate clusters, never noise, never a filter.
2. **Gothic** — arches, bones, candles, ruined grandeur.
3. **Readable** — silhouette first; if it reads at 24px it is good.
4. **Muted-but-colorful** — saturated accents on desaturated bases, never neon soup.
5. **Dangerous** — even a flowerpot looks like it has seen a murder.

Reference feeling: a premium indie pixel crawler. Not a prototype, not a tech demo, and not a
copy of any existing game. All designs in this project are original.

### Anti-goals

| Never | Instead |
| --- | --- |
| `ctx.arc()` creature bodies | authored pixel grids |
| smooth vector curves | stepped pixel diagonals |
| CSS/canvas gradients as shading | 2–4 tone ramps + dithering |
| emoji | pixel icon sprites |
| pixelation post-filter | real low-res authoring |
| random hex colors | the master palette below |
| PNG sprite sheets | SVG-authored, canvas-cached sprites |

## 2. Pipeline: pixel grids → SVG → cached canvas

Assets are authored as **character grids** (one char = one logical pixel) plus the shared master
palette. `src/art/PixelSprite.js` then:

1. merges equal-color horizontal runs into `<rect>` spans,
2. emits **real SVG** (`shape-rendering="crispEdges"`, integer coordinates only, zero curves,
   zero gradients, zero anti-aliasing),
3. rasterizes that SVG once into an offscreen canvas at load time,
4. hands the game a cached, immutable bitmap.

`sprite.toSVG()` returns the SVG source for any asset, and `?exportSvg=1` on the game URL dumps
the whole library as downloadable `.svg` files using the naming convention in §12. There is no
PNG anywhere in the pipeline.

Environment filler (rocks, trees, bushes, grass, rubble, cracks, floor grain) is generated by
**seeded pixel-art constructors** in `src/art/sprites/environment.js`. They stamp the same pixel
primitives a human would — stepped silhouette, 3-tone ramp, moss dither — so a single generator
yields 10 coherent variants instead of 10 hand-copied grids. Characters are never generated this
way; every creature is hand-authored.

### Hard rendering rules

- `ctx.imageSmoothingEnabled = false` on every context, always.
- Camera zoom is an **integer** (device pixels per logical pixel). Never fractional.
- Sprite blits happen at integer device coordinates (`Math.round`) — no sub-pixel drift.
- 1 logical art pixel = 1 world unit = `zoom` device pixels.

### Palette discipline

- One asset uses **at most 8** palette entries (excluding outline `0` and transparent).
- Shade with a **3-step ramp** (shadow / base / light). 4 steps only on 32px+ assets.
- `Q` pure white is reserved for hit flashes and single-pixel speculars. Never a fill.

## 5. Outlines

- Every free-standing object gets a **1px outline** in `0` (void black), or in the object's
  darkest own tone when it must sit quietly in the background (distant rubble, floor cracks).
- Outlines are **selective**: bottom and outward-facing edges get the outline; top edges facing
  the light may drop it to let the highlight breathe.
- Diagonals are **stepped** — 1px, 2px, 3px runs. Never a 1px staircase of alternating single
  pixels on a large form (that reads as noise).
- Characters additionally get a **rim separation**: the pixel row directly under the sprite is a
  contact shadow (see §7), which keeps them off the floor texture.

## 6. Light & shading

**The light comes from the upper-left, unless a local light source overrides it.**

- Top and upper-left faces: light tone.
- Right and lower faces: base tone.
- Bottom / underside / occluded: shadow tone.
- Interior detail (belts, cracks, joints): shadow tone, 1px.
- Specular: a single `Q` or `9`/`O` pixel, only on metal, ice, gems, wet stone.

**Dithering** is a 50% checkerboard, used only for:
- material transitions (stone → moss, floor → water),
- fog and volume falloff,
- light halo edges.

Never dither to fake a gradient across a whole object.

**Lighting engine** (`src/art/Lighting.js`) is a quarter-resolution lightmap composited with
`multiply`. Because it is upscaled with smoothing off, its falloff is chunky and pixelated by
construction. Light radii are quantized to 8-unit steps so halos step rather than fade.

| Source | Color | Radius |
| --- | --- | --- |
| Torch / brazier | `S` torch orange | 96–128 |
| Candle | `R` candle light | 48 |
| Player aura | biome-tinted warm | 88 |
| Magic prop / shrine | `T` or `U` | 72 |
| Lava crack | `o` | 64 |
| Boss (phase 3) | boss accent | 160 |

## 7. Characters

### Proportions

Chunky heroic-chibi. Head is large enough to carry expression, body is stocky enough to carry a
silhouette.

- Total height 28 logical px (player) — head 9, torso 10, legs 9.
- Head width 10–12, shoulders 12–14, waist 8–10.
- Eyes: 1–2px, always in the darkest socket tone with a 1px light dot. Glowing eyes for undead
  and elites.
- Hands are 2×2 blocks. Feet are 3×2 blocks.
- **Contact shadow**: a 1px-tall, 60%-width dark ellipse-ish bar under every character.

### Player: "The Delver"

A dungeon explorer in dark leather over a deep-crimson gambeson, a worn hooded cloak, small
asymmetric pauldron on the left shoulder, gloves, buckled boots, and a weapon that glows with
whatever element it carries.

- Cloak reads as the signature shape: it flares behind the silhouette and lags one frame behind
  movement.
- Cloak color: crimson `j`/`k` (warrior), forest `v`/`w` (rogue), arcane `F`/`G` (mage).
- Skin `J`/`K`/`L`, leather `b`/`c`, steel `f`/`g`.
- The player is the **brightest character on screen**, always, and is drawn with a subtle warm
  light aura so it never gets lost in a crowd (§11).

### Facing

4 directions: `down`, `up`, `left`, `right`. `left` is the mirrored `right` grid. Facing follows
the **aim vector** (mouse), because attacks follow aim. Weapon anchor points are defined per
direction and per frame, so a swing always leaves the hand.

### Animation

Frames are authored as one base grid plus a **rig** describing row bands (head / torso / arms /
legs / cloak). Frames are produced by pixel-space band transforms — integer row shifts, band
offsets, row insert/remove for squash — never by interpolation.

| State | Frames | FPS | Feel |
| --- | --- | --- | --- |
| idle | 2 | 4 | 1px breathe on head + torso, cloak sway |
| walk | 4 | 10 | 2px body bob, legs alternate, cloak trails |
| attack | 3 | 18 | anticipation (−1 lean) → strike (+2 lean) → recover |
| hurt | 1 | — | white `Q` flash + 2px knock-back lean |
| dodge | 1 | — | forward lean + afterimage trail |
| death | 4 | 6 | collapse: fold legs, drop head, dissolve to particles |

Enemies use the same rig system with `idle 2 / walk 4 / attack 2 / hurt 1 / death 3`.

weapon, and the five animation states.

### Visual hierarchy

**Normal** — base sprite, 1px black outline, small contact shadow.

**Elite** — same sprite plus:
- 1px outline replaced by the elite modifier color,
- glowing eyes in the modifier color,
- an orbiting 3-particle aura,
- a stepped pixel ground ring,
- +15% scale (still integer-snapped).

**Boss** — 64×64, unique silhouette, unique palette, never a scaled-up normal enemy.
- Phase 1: base. Phase 2: armor cracks, one eye lights. Phase 3: enraged palette shift, both
  eyes blaze, permanent particle aura, 160-radius colored light that recolors the room.
- Every telegraph is a **stepped pixel shape** (ring / cone / cross), pulsing on an 8-frame loop,
  in `l` bright red, never a soft alpha blob.

## 9. Environment

Rooms must read as **places**, not rectangles.

### Floors

Assembled from a 32×32 tileset per biome: `floor_center`, three grain variants, `floor_cracked`,
`floor_broken`, `floor_moss`, `floor_puddle`, plus a `floor_edge_*` set (4 edges + 4 outer
corners + 4 inner corners) chosen by an **autotiling bitmask** against the walkable mask.

Floor tiles carry visible individual stones: 2–4 stone blocks per tile with 1px mortar joints in
the shadow tone, one lit top edge per stone. Variants are picked by a hash of tile coordinates so
the same dungeon seed always produces the same floor.

### Walls

Walls are never flat rectangles. Each wall run renders as:

1. **top cap** — 8px band of lit stone above the wall line (the "thickness" of the wall),
2. **face** — brick courses, offset every other row, 1px mortar,
3. **base shadow** — 3px dark band where the wall meets the floor,
4. **detail pass** — cracks, moss runs, seeped water, iron rings, chains, banner mounts.

Doorways get an arch: two jamb stones and a 3-step keystone curve.

### Density rules (§ readability first)

Every room gets `room.seed` from the dungeon RNG, so decoration is **random per run and
identical for the same dungeon seed**. Decoration is purely visual, never collidable, and never
placed where it can hide a threat.

| Zone | Rule |
| --- | --- |
| Wall band (0–40 from wall) | dense: rubble, rocks, bones, chains, wall props |
| Corners | one large anchor prop (statue / pillar / bookshelf / brazier) |
| Combat center (inner 60%) | ≤2 flat ground decals only, no tall props |
| Around obstacles | scatter that explains the obstacle (rubble around a broken pillar) |
| Doorways | 24-unit clear radius, always |
| Paths between doors | clear corridor of 40 units |

Tall props are additionally forbidden within 48 units of a spawn point, and everything taller
than 20px gets 70% alpha when the player is behind it.

### Environmental storytelling

Rooms roll a **scene** from a per-room-type table and lay out a hand-designed prop cluster:

- `ransacked` — toppled table, scattered books, blood decal, broken sword in the floor.
- `shrine` — altar, 2 candles, 2 statues, floating rune particles.
- `battlefield` — bones, 3 planted swords, cracked shield, torn banner.
- `crypt` — 3 tombstones, candles, skull pile, cracked statue.
- `larder` — barrels, crates, hanging chains, pots.
- `library` — bookshelves, scattered books, lectern.
- `overgrown` — roots through the floor, mushrooms, vines, bushes.
- `forge` — anvil, brazier, hanging tools, ash.

## 10. Biome identities

Each biome overrides the tileset palette, ambient light, decoration tables, and atmosphere
particles. Biome palettes are **remaps of the master palette**, never new colors.

### 1. Forgotten Catacombs
Grey-violet stone, damp mortar, moss in the joints, candle stubs everywhere, bone piles, tomb
niches, cracked flagstones, roots pushing through the ceiling.
Ambient `#1a1724` · light `R` candle · particles: slow dust motes.
Props: tombstone, skull pile, candle, bone, chain, cracked statue, brazier, urn.

### 2. Cursed Forest
Wet black earth over stone, twisted dead trees, glowing mushrooms, thick roots, dead leaves,
knee-high fog, bushes.
Ambient `#101c14` · light `x` sickly green · particles: drifting spores, falling leaves.
Props: dead tree, root arch, mushroom cluster, bush, log, standing stone, vine.

### 3. Infernal Depths
Black volcanic rock, glowing lava cracks in the floor, ash drifts, iron spikes, demonic arches,
chained braziers, scorch marks.
Ambient `#1c0c08` · light `o` ember · particles: rising embers, ash fall.
Props: brazier, lava crack, obsidian spike, chain, demon statue, ash pile, bone.

### 4. Frozen Abyss
Blue-grey ice over old stone, frozen ruins, icicles, snow drifts, frozen corpses, cracked frozen
water.
Ambient `#0e2438` · light `C` frost · particles: falling snow, ice glints.
Props: icicle cluster, ice block, frozen pillar, snow drift, frozen statue, ice spike.

### 5. Void Citadel
Black basalt with purple energy in the seams, floating stone fragments, impossible geometry,
glowing glyph circles, star-holes in the floor.
Ambient `#12081c` · light `U` mystic · particles: cosmic motes, upward energy streaks.
Props: floating fragment, glyph circle, void obelisk, shattered pillar, rune stone.

## 11. Visual hierarchy (non-negotiable)

Brightness, contrast, outline weight and VFX are budgeted in this order:

1. **Player** — brightest silhouette, warm aura, always drawn last among characters.
2. **Incoming danger** — telegraphs, enemy projectiles: highest-contrast reds/whites, pulsing.
3. **Elite enemies** — colored outline + aura.
4. **Boss** — large, colored light, but tuned so it never out-reads its own telegraphs.
5. **Loot** — rarity glow + float bob.
6. **Normal enemies** — clear silhouette, mid contrast.
7. **Environment props** — mid-dark, low saturation.
8. **Floor / background detail** — lowest contrast; must never approach character contrast.

Practical enforcement:
- Floor tiles stay within neutrals `1–5`; characters use `6+` for their lightest tones.
- No environment asset uses `Q`, `9`, `O`, `t`, `p`, `l`, `z`, `D`, `H` as a large fill.
- Entities y-sort so nothing important is occluded ambiguously.

## 12. VFX

Particles are **squares**, integer-positioned, integer-sized (1, 2, 3, 4), never circles, never
soft. Size shrinks in steps over life; alpha quantizes to 4 levels.

| Effect | Recipe |
| --- | --- |
| hit | 5 directional 2px sparks `9`, 1-frame `Q` flash on target |
| crit | 10 sparks + 4-arm pixel star `t`, screen shake, bigger flash |
| blood | 6 `j`/`k` 2px drops, gravity, leaves a floor decal |
| fire | rising `o`/`p` embers, drag, plus `m` smoke squares |
| ice | 6 angular `C`/`D` 3px shards, no gravity, glint |
| lightning | jagged 1px polyline arcs `p`→`T`, 2-frame life |
| poison | `z` bubbles rising, popping into 4 dots |
| arcane | `G`/`H` motes orbiting inward |
| death | 12 particles in the enemy's own palette + vertical dissolve of the sprite |
| loot beam | rarity-colored 2px column + orbiting motes |
| level up | 24 ascending `t` sparkles + 3 expanding stepped rings |
| dash | 3 fading afterimages of the player silhouette |

**Damage numbers** use the bitmap pixel font, drawn in-world on the canvas:
normal = 1× `9`; crit = 2× `t` with a `CRIT!` tag, a 4-frame bounce and a 1px black outline;
elemental damage uses the element color. Numbers rise, ease out, and fade in 4 alpha steps.

## 13. UI

The HUD is a **carved stone and tarnished brass** interface. It belongs to the dungeon.

- Panels: 3px stepped border (dark outer `0`, mid `4`, light inner `6`), stone-noise fill,
  brass corner brackets. Built with pixel-precise `box-shadow` steps and `border-image`-free
  geometry — no `border-radius`, no blur, no soft shadow.
- Buttons: 2px stepped bevel, light top-left, dark bottom-right; pressed state inverts the bevel
  and offsets content 1px down-right.
- Bars: black socket, 1px inner shadow, hard-edged fill, 1px highlight line on the top row of the
  fill, notch ticks every 25%.
- Item slots: 2px frame in the rarity color, rarity glow as a stepped box-shadow, icon rendered
  from the sprite library (never emoji).
- Font: `Silkscreen` / `Press Start 2P` with a system fallback stack; `font-smooth: never`.
  Canvas text uses the built-in 5×7 bitmap font.
- Level-up: three stone cards with rarity-tinted brackets, icon plate, and a hover lift of
  exactly 2px (no scale, no blur).
- Boss bar: wide brass frame, segmented per phase, cracks as HP drops, name in gold caps.

## 15. Performance budget

- All sprites rasterized **once** at boot; nothing constructs an `Image`, SVG or canvas per frame.
- Tinted/flashed variants are cached per (sprite, tint) pair, generated lazily, capped.
- Static room decoration is baked into a per-room offscreen canvas and blitted as one image,
  invalidated only on floor change.
- Viewport culling on every draw list; y-sorted single pass.
- Particles pooled (existing `ObjectPool`), hard cap, squares only.
- Lightmap at quarter resolution.
- Target: 60 fps with 120 entities and 400 particles at 1920×1080.

## 16. Acceptance checklist for any new asset

- [ ] Reads as a silhouette at 100% zoom.
- [ ] Uses only master palette characters.
- [ ] ≤8 colors, 3-tone ramp, light from upper-left.
- [ ] 1px `0` outline, stepped diagonals, no isolated single-pixel noise.
- [ ] Contact shadow if it stands on the ground.
- [ ] Sits in its resolution class from §3.
- [ ] Named per §14 and registered in `AssetRegistry`.
- [ ] Contrast is below the player's (unless it is the player).
- [ ] No curve, no gradient, no anti-aliased edge, no emoji.
